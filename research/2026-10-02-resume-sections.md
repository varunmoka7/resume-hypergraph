# What sections resumes and CVs contain, and how they map onto the graph model

Date: 2026-10-02. Time-boxed web research (about 20 searches). Many of the pages that turned up are career-advice blogs and templates, not primary sources. The only primary or institutional sources are the university pages, AAFP, Europass, and LinkedIn Help. Where a claim rests on a blog only, it is marked "blog".

Model reminder: person at the centre; nodes (things done) in labelled groups; skills are hyperedges linking every node where used, each link carrying one sentence.

## 2. Recommended mapping

Legend: (a) group of nodes, (b) skills/hyperedges, (c) attribute on an existing node, (d) profile-level text, (e) leave out by default.

| Section | Mapping | One-line reason |
|---|---|---|
| Profile / Summary | (d) | Free text about the person, not a thing done. |
| Contact | (d) | Links and contact are profile data. Show only what the owner picks. |
| Work experience | (a) group "Work" | The core node type. Multiple roles: see section 3. |
| Education | (a) group "Education" | A degree is a place and period with skills used. Grade, honours, thesis title go on the node as (c). |
| Skills | (b) | This is exactly what hyperedges are. A skill with no node link is a profile-level tag, shown dim. |
| Languages | (c) on profile, plus (b) only when used at work | Level is an attribute of the person. Making "German" a hyperedge only works if some node actually used it. See section 3. |
| Certifications | (a) group "Credentials" when it has its own date and issuer; also (b) when it names a skill | A certificate is a dated, issued-by-someone thing. Often the skill name inside it should link. |
| Professional licences and registrations | (a) group "Credentials" | Same shape as certifications. Never show numbers. |
| Projects | (a) group "Projects" | Existing group. |
| Open source | (a) group "Projects" with a "kind" attribute | A repo is a project. A long list of small contributions to one project is one node. |
| Hackathons / competitions | (a) group "Projects" or "Awards" | One event is one build. Placement is an outcome attribute (c). |
| Publications | (a) group "Publications" | Dated, with a venue, link. Needs the long-list rule. |
| Patents | (a) group "Publications" (subtype patent) | Same shape as a paper: authors, number, date. |
| Grants / funding | (a) group "Funding & Awards", or (c) on the research node it funded | Funding is an event with an amount. If it clearly belongs to one project, attach it there. |
| Teaching | (a) group "Teaching" | Course, institution, term. Many courses at one place: group by institution (section 3). |
| Supervision | (c) on a Teaching or Work node ("supervised 6 MSc students") | Usually a count and a level, rarely worth its own node. Make it a node only if it is the main activity. |
| Invited talks / presentations | (a) group "Talks & Press" | Dated events with a venue. Long list rule applies. |
| Service (peer review, committees) | (a) group "Service & Membership", merged with memberships | Dated roles at a body. |
| Research experience | (a) group "Work" or "Research" | It is a job or lab position. |
| Awards / honours / scholarships | (c) when tied to one node (a scholarship for a degree); otherwise (a) group "Awards" | Avoid a mass of tiny nodes. Free-standing awards get a group. |
| Memberships / societies | (a) group "Service & Membership" | Body plus years. |
| Volunteering | (a) group "Volunteering" | Same shape as work. |
| Extracurricular / leadership | (a) group "Volunteering & Activities" | Role at a student body. |
| Internships / placements / co-op | (a) group "Work", with a "kind: internship" attribute | Same shape as a job. Keeps the grouping from exploding. |
| Clinical rotations | (c) on the Education node, or (a) group "Work" if long and detailed | New grads treat them as experience (nursing sources). Hours and unit are attributes. |
| Physician residency / fellowship | (a) group "Education" or "Training" | Formal training with institution and dates. |
| Representative matters | (a) group "Work" as child entries under the firm, or group "Projects" if client-facing | Each matter has a role and outcome. Client names need consent (section 5). |
| Clerkships | (a) group "Work" | A one-year job. |
| Moot court / journals | (c) on the Education node | Small, tied to the degree. |
| Exhibitions | (a) group "Exhibitions & Shows" | Dated events with a venue. |
| Collections / commissions | (a) group "Exhibitions & Shows" or "Clients" | Buyer plus work plus year. |
| Bibliography / press | (a) group "Talks & Press" | Dated external items. |
| Residencies | (a) group "Funding & Awards" or "Training" | Programme, place, dates. |
| Clients | (a) group "Clients" or children of a single "Freelance" node | See freelance rule. |
| Gallery affiliation | (c) on the profile | One line of status. |
| Military service | (a) group "Work" (service as employer; one node per posting) | Looks like jobs. Rank is an attribute (c). |
| Security clearance | (c) on profile, or (e) | Visible clearance can be a security issue, the owner decides. |
| Military training / decorations | (a) group "Credentials" or "Awards" | Same as certs and awards. |
| Tickets / trade licences | (a) group "Credentials" | Same as licences. |
| Apprenticeship | (a) group "Education" or "Work" (owner picks) | Both paid work and training. |
| Board seats / advisory roles | (a) group "Boards & Advisory" | Concurrent, dated roles at organisations. |
| Executive development | (a) group "Education" | Short courses at schools. |
| Career break | (a) a dated node in group "Work" with kind "break" and no skills required | Keeps the timeline honest. Optional, owner decides. |
| Interests / hobbies | (a) group "Hobbies" | Already exists. |
| Entrepreneurship | (a) group "Entrepreneurship" | Already exists. |
| Part-time jobs | (a) group "Part-time" or "Work" with a flag | Already exists. Consider merging into Work with a flag (section 4). |
| Digital skills / driving licence | (b) for digital skills; (c) for driving licence, default (e) | Digital skills are skills. A driving licence matters only where the job needs it. |
| References | (e) | Contact data for third parties. Never publish without their consent. |
| Declaration | (e) | A legal formality for a paper form. No use on a website. |
| Personal data (DOB, marital status, father's name, religion, photo etc.) | (e), see section 5 | Not needed to understand the work. |
| Featured / recommendations | (a) group "Talks & Press" (featured) or (e) (recommendations, someone else's words) | Featured items are links. Recommendations need the author's permission. |
| Test scores | (c) on Education | A number attached to a study period. |
| US federal hours/week, GS grade | (c) on the Work node | Attribute of a job. |

## 3. Tricky cases

**One employer, several roles.** Recommendation: one node per employer, with a list of roles inside it (title, start, end). Skills link to the employer node, not to each role. Optional: a skill link may carry a `role` tag when the sentence concerns one role. Reason: promotions are the usual case (LinkedIn also nests multiple positions under one company), and one node per role would show one company as several unrelated dots. Exception: if roles are in clearly different functions or places (engineer, then sales lead), the owner can split into two nodes sharing an `employer` field, which the viewer can colour or cluster alike.

**A section that is both a node and a skill (languages, certifications).** Recommendation: store the fact once, in one place, and let the other side be a link.
- Languages: a profile attribute list (language plus level). The language also becomes a skill hyperedge only when the owner links it to a node and writes a sentence ("translated contracts DE-EN"). Otherwise render as a plain badge, not a hyperedge. A hyperedge with zero nodes is clutter.
- Certifications: a node in "Credentials". If the title names a skill ("AWS Solutions Architect"), the owner may link that skill to the cert node with the sentence "passed the exam", and to the work nodes where it was used. The exam and the use stay separate evidence. Do not auto-create skills from certificate titles, as the parse is too noisy.

**Undated entries.** Common in skills lists, hobbies, interests, some publications and exhibitions, some trade tickets. Recommendation: dates are optional on every node. Undated nodes are not placed on the timeline and sort last inside their group, with no "present" or fake date. The importer must not invent a date. The viewer should show "no date" instead of leaving the field empty without explanation.

**Very long lists (40 publications, 60 talks).** Recommendation: do not draw 40 nodes. Three options, in order:
1. Collapse the group into one summary node ("Publications, 40") that expands into a list panel on click (a list, not a graph).
2. Show the top N the owner marks as "selected" (artist and academic CVs label these "Selected exhibitions" or "Selected publications" themselves, per the artist and academic sources), the rest in the panel.
3. Group by year or by type (journal, conference, book chapter) where the CV already uses these sub-headings (the academic CV sources describe such sub-headings).
Skills link to the summary node, with one sentence per link, not per paper. Reason: the graph is for overview; a dense list belongs in a table. A node threshold (say above 12 per group) can trigger the collapse automatically.

**Overlapping or concurrent roles.** Common with board seats, advisory roles, part-time and freelance work next to a main job, and students. Recommendation: allow overlapping date ranges on any nodes; never assume they are sequential. Do not infer a "gap" or "left to join" from overlap. The timeline view shows lanes (parallel bars). Board and advisory roles by nature run in parallel with a main job (executive resume sources place them in a separate section for this reason).

**Career gaps.** Recommendation: the model does not detect or flag gaps. Gaps are blank space on the timeline. If the owner wants to explain one, they add a "break" node (parental leave, sabbatical, caregiving, relocation) with dates and an optional sentence. Career-advice sources agree it is usually a short dated entry in the experience section with a plain label. The owner may attach skills to it (courses, freelance work, volunteering done during the break). Parental leave is a protected status in many countries, so the default should be "owner chooses a label, including a neutral one such as 'Career break'".

**Freelance work with many clients.** Recommendation: one parent node for the freelance practice (role, dates), with clients as list entries inside it (client, year, one sentence). Promote a client to its own node only when the owner has real detail (a case study). Skills link to the parent node, with a sentence that may name the client. Reason: 30 clients as nodes would drown the graph; a creative or consultant CV often lists clients as a flat "Selected clients" list. Client names may be confidential (section 5).

**Sections with custom or unknown headings.** Recommendation: see rule in section 4. In short: never drop content. Unmatched headings become a group with the heading as typed.

Other cases found:
- **Two-column German table layout and Europass:** both are Berufserfahrung and Ausbildung with the date in the left column. Importer must read dates from the left cell; the semantics are the same as a normal resume.
- **Nursing and medical licences at the top of the page** (credentials block on page one): position in the source tells nothing about the type. Map by content, not by page order.
- **Dual entries:** a PhD appears in Education, Research experience, Teaching and Publications. Keep it one Education node plus separate nodes for the others, and let skills tie them together. Do not merge.
- **Anonymised matters:** law resumes name practice area and role but often cannot name the client. Allow a node with no org.
- **Work done for one client by an agency employee:** two orgs on one entry (employer, client). Add an optional `client` field to the Work node.

## 4. Proposed default groups (12) and the fallback rule

1. **Work** (employment, internships, clerkships, military service, research positions; `kind` attribute: job, internship, military, clerkship, break)
2. **Education** (degrees, apprenticeships, residencies, executive programmes; attributes for grade, honours, rotations)
3. **Projects** (personal projects, open source, hackathons, portfolio pieces, case studies)
4. **Entrepreneurship** (founded or self-employed ventures)
5. **Freelance & Clients** (freelance practice with client list; can be merged into Work with a flag if the owner prefers)
6. **Research & Publications** (papers, patents, books, preprints)
7. **Teaching & Mentoring** (courses taught, supervision, workshops)
8. **Talks & Press** (invited talks, conference talks, press, interviews, bibliography)
9. **Exhibitions & Works** (exhibitions, shows, commissions, collections, residencies)
10. **Credentials** (licences, certifications, tickets, registrations, board certification, security clearance if the owner shows it)
11. **Awards & Funding** (awards, scholarships, grants, fellowships)
12. **Service & Membership** (boards and advisory roles, committees, peer review, societies, professional bodies)
13. **Volunteering & Activities** (volunteering, student organisations, community roles)
14. **Hobbies**

That is 14. The current six (work, education, projects, entrepreneurship, part-time jobs, hobbies) map in as: work, education, projects, entrepreneurship, hobbies stay; part-time jobs become Work with `kind: part-time` (or stay as is, if the owner wants them separate). If the project wants fewer, merge 5 into Work and 13 into Service & Membership, giving 12.

Profile-level (not groups): summary, contact and links, languages with level, driving licence (optional), skills with no node.

**Rule for a heading that matches none.**
1. Normalise the heading (lowercase, strip punctuation, handle common synonyms and German and Spanish equivalents from an alias table).
2. If it matches a known alias, use that group.
3. If not, try matching on the entry shape: has dates and an organisation and sounds like a role, use Work; has only a venue and year, use Talks & Press or Exhibitions & Works; is a short list of terms with no dates, treat as skills or interests.
4. If still unsure, create a new group named exactly as the heading and show it as a normal group. Never place the content under Work by default, never drop it, never rename it. Flag it in the import report so the owner can choose a standard group later.
5. Cap: if a custom group has more than about 12 entries, apply the long-list collapse.
Reason: guessing silently hides content or invents a false story (an unknown "Founding member" under Work reads as a job). Showing the heading as typed is honest and cheap, and the owner can remap it.

## 5. Sensitive data

Default in all cases: not published unless the owner turns it on, per field, with a plain warning. A public page is searchable, scrapable, and cannot be taken back, which is different from a CV sent to one employer. This is a design recommendation on my part. The legal facts below are from the sources found; I am not giving legal advice.

| Field | Where common | Recommendation | Evidence |
|---|---|---|---|
| Date of birth and place of birth | Germany (common but optional), India (biodata), Europass | Drop by default. Never show full date; if asked, show age range or nothing. Opt-in only. | German sources: DOB is customary but voluntary, employer cannot demand it (AGG, blog sources). US and UK sources: leave it out. DOB combined with name is a common identity-theft and password-reset input (my reasoning). |
| Photo | Germany, Austria, much of Asia and the Middle East; actors, real estate in US/UK | Optional, off by default. Ask: "this is public; faces are scrapable". Owner uploads separately; do not pull from the CV. | Photo voluntary in Germany since AGG 2006 (blog). US and UK sources say omit. |
| Marital status, children | Germany (older style), India | Drop. Do not import. | German sources say it tells nothing about qualification; UK Equality Act 2010 context. |
| Father's or guardian's name | Indian government and PSU biodata | Drop. Never import. | Biodata convention (blog); no relevance to public presentation, and used in identity verification (my reasoning). |
| Nationality / citizenship | Germany, Europass, India | Opt-in. Work authorisation ("EU citizen", "visa needed") can be useful, but the owner should write it deliberately. | Standard in German personal data (blog). |
| Religion, caste, category | India (only where a form asks), some Middle East | Drop. Never import. | German source: religion cannot be asked under AGG s.1. Indian guidance: include only where a form asks. |
| Gender | India, some others | Drop. | Same reasoning. |
| Home address | Germany, India, Europass, older US/UK | Drop the street address. City or region only, opt-in. | Modern US and UK advice: city and region; privacy and stalking risk (my reasoning). |
| Phone number | all | Opt-in, off by default; a contact form or email is safer. | Scraping and spam. |
| Email | all | Opt-in. Offer a link or form instead. | Same. |
| Security clearance | veterans, defence | Owner decides; show only level if at all, never agency detail. | Sources advise including it as an asset on a CV; a public site is a different audience. |
| Licence and registration numbers (nursing, medical, bar, trade) | licensed professions | Drop numbers. Show type, jurisdiction, year. | AAFP advises listing states without license numbers. |
| Salary, hours, supervisor contact | US federal resumes | Drop. | These are form requirements for the application, not for display. |
| References and referees | UK, AU, IN, physician | Drop; third parties have not agreed to publication. | Common sense and data protection law, not a direct source. |
| Client names | freelance, law, consulting | Opt-in per client. Law resumes often cannot name them at all. | Law sources mention matter outcomes and named clients, but confidentiality may restrict naming (my reasoning; ask the owner). |
| Patient or case detail | nursing, law, medicine | Never import free-text details. Warn on any entry containing patient or case identifiers. | Patient confidentiality and legal privilege; my reasoning. |
| Names of supervised students | academic | Default to counts, not names. | Students may not want to be listed (my reasoning). |
| Employer-confidential achievements | executives, consulting | Owner confirms before publishing. | Contract terms. |

Where sources disagree: German career sites split on whether DOB and photo are still expected. One says "customary but voluntary", another that photos are "üblich" but not required; I found none claiming they are required. Several Indian blogs say personal details are now outdated for private-sector and multinational jobs, while the same pages say government biodata still wants them. For a public website neither tradition is a reason to publish.
